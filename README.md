# Разбор — прототип ядра

Рабочий прототип приложения для изучения языка по видео с YouTube (аналог Linglass).
Это **Фаза 0** из плана: проверка самых рискованных допущений до продуктовой разработки.

## Запуск

```bash
cd server && npm install && npm start    # бэкенд, http://localhost:8788
./serve.sh                               # фронт,   http://localhost:8777/index.html
```

Фронтенд ищет бэкенд по адресу `http://localhost:8788`. Можно переопределить
параметром `?api=<адрес>` — так живая версия на Pages работает с локальным бэкендом.

**Открывать только по http.** По `file://` не работает: браузер считает такие страницы
уникальным origin, и `postMessage` к плееру YouTube не проходит — плеер не управляется.
Это выяснилось на живом тесте, не из документации.

## Что уже работает

- Плеер YouTube через официальный IFrame API, расшифровка **под** плеером (оверлей поверх
  плеера запрещён правилами YouTube, см. план).
- Караоке-подсветка слова, синхронная с речью. Опрос `getCurrentTime()` в `requestAnimationFrame`
  плюс интерполяция между тиками: события `timeupdate` у IFrame API нет.
- **Русская дорожка под каждой репликой** — переводит Claude сразу после вставки ссылки,
  поток пачек, начало готово за ~15 секунд. Кнопка «Русский» выключает её целиком.
- **Фильтр по уровню (B1 / B2 / B2+)** — Claude оценивает сложность каждой реплики по CEFR
  (шкала A / B1 / B2 / C), и перевод остаётся только под репликами на или выше выбранного
  уровня: простое читается по-английски, сложное подстраховано. Кэш в data/levels/.
- **Офлайн-пакет** — кнопка «Офлайн» скачивает видео (480p) и собирает автономную
  страницу: реплики, перевод, уровни и караоке зашиты внутрь, плеер — локальный <video>.
  Два файла AirDrop'ом на телефон, открывать из приложения с файлами (Documents и т.п.) —
  сеть не нужна. Колода уезжает снимком вместе с пакетом (у страницы на телефоне свой
  localStorage), фразы в карточках играются из локального видео медиафрагментом.
  Сборка: tools/build_offline.py, файлы в data/offline/<vid>/.
- Клик по слову — перевод от Claude в значении из фразы, не первый словарный, плюс сама фраза.
- **Радар идиом** — при загрузке видео Claude сканирует расшифровку и помечает пунктиром
  выражения, которые надо учить целиком (фразовые глаголы, идиомы, устойчивые сочетания) —
  до первого клика. Клик по любому слову выражения разбирает его целиком, повторный клик
  по нажатому слову сжимает выбор до одного. Кэш в data/idioms/.
- **Словосочетания, а не только слова** — клик по соседнему слову в контексте (или
  Shift+клик в расшифровке) растягивает разбор до фразы: «plow through», «get away with»
  переводятся и сохраняются как целое. Клоз прячет всю фразу, подчёркивание в расшифровке
  ловит последовательность слов, Anki-экспорт делает один пропуск на выражение.
- Сохранение слова в колоду вместе с контекстом и таймкодом.
- **В карточке повторения — вырезанный кусок видео с этой фразой** (~6 с, 480p, ~200 КБ).
  В колоде фразы из разных видео, и грузить двухчасовой подкаст ради одной реплики нельзя;
  клип режется в момент сохранения слова и лежит на диске.
- **Слова из колоды подчёркиваются прямо в расшифровке.** Сохранил слово — все его вхождения
  в тексте помечаются. Отсюда же считается «понятно, %» — основа подбора видео по принципу i+1.
- **Повторение по FSRS-4.5** — две независимые величины на карточку: стабильность
  (когда вспоминаемость упадёт до 90%) и сложность лично для тебя. Тяжёлое слово
  получает короткие интервалы, не ломая длинные у лёгких; «Забыл» роняет стабильность,
  но не обнуляет накопленное. Оценка в четыре градации. Очередь — самые просроченные
  первыми: у них вспоминаемость упала ниже всех.
- **Клоз-карточки** — по умолчанию карточка показывает фразу с пропуском на месте
  слова, а не слово в вакууме: вспоминание в контексте прочнее. Кнопка «Клоз» переключает.
- **Режим «по фразам»** — пауза на конце каждой реплики, пробел ведёт к следующей.
  Без паузы речь идёт потоком и разбирать её некогда.
- **Режим «На слух»** — текст реплики размыт, пока фраза не отзвучала: глаз читает
  быстрее, чем ухо слышит, и при видимых субтитрах аудирование подменяется чтением.
  Прозвучавшая реплика открывается — сверить услышанное можно сразу. Подсмотреть
  досрочно: наведение (только английский), клик или `T`. В паре с режимом «по фразам»
  получается цикл: фраза доиграла → пауза → вспоминаешь → `T` → сверился → пробел.
- **Диктант** — реплика играет ровно одна и плеер встаёт (иначе следующая фраза
  подсказывает ответ на слух), ты печатаешь на слух, расхождения показываются пословно
  (расстояние редактирования по словам, регистр и пунктуация не в счёт). Enter проверяет,
  второй Enter уводит дальше, ⌘/Ctrl+Enter переслушивает не отрывая рук (тот же жест —
  в наборе ответа повтора). **Нерасслышанное слово кликабельно прямо в проверке**:
  клик переводит его в контексте фразы и кладёт карточкой в колоду (с нарезкой) —
  пробел в аудировании сразу уходит в повторение, не выбивая из ритма диктанта.
  Вкладка открывается на текущей фразе видео — посмотрел
  кусок, тут же продиктовал его; позиция помнится по каждому видео отдельно.
- **Прогресс** — слова за неделю, повторы, минуты видео, средняя вспоминаемость колоды
  по FSRS, «выучено прочно» (интервал от трёх недель), график активности за 14 дней
  и серия дней подряд: пустой сегодняшний день серию не рвёт — вечер ещё впереди.
- **Библиотека видео** — история открытого с числом реплик и покрытием («понятно N%»),
  клик открывает заново. Это и есть основа подбора следующего видео по принципу i+1.
- **Видео продолжается с места остановки** — позиция каждого видео запоминается
  (раз в 5 секунд во время игры), и перезагрузка страницы, открытие из библиотеки
  и офлайн-пакет возвращают туда, где остановился: длинный подкаст смотрится
  в несколько подходов, а не листается с нуля. Начало (до 30 с) и последние
  20 секунд не в счёт — досмотренное открывается сначала.
- **Экспорт в Anki** — кнопка «В Anki» собирает .apkg: клоз-карточка с вырезанным
  видеофрагментом на лицевой стороне, слово с переводом на обороте (tools/export_anki.py,
  genanki). Повторный экспорт обновляет карточки, а не плодит дубли.
- «Переслушать фразу» и «Зациклить» — перемотка внутри плеера вместо вырезания аудио
  (вырезать аудио правила YouTube запрещают).
- Скорость 0.75×, горячие клавиши: пробел, стрелки по репликам, `R` — переслушать.
- Тёмная и светлая темы, мобильная раскладка, `prefers-reduced-motion`.

## Данные

Реплики — **настоящие**, из автосубтитров YouTube в формате `json3`
(TED-talk Тима Урбана про прокрастинацию, `arj7oStGLkU`).

`tools/normalize_json3.py` решает две реальные проблемы формата:

1. **Пословный тайминг** лежит как `tStartMs` + `tOffsetMs` у каждого сегмента — именно
   поэтому караоке-подсветка работает без forced alignment.
2. **Roll-up:** ASR перерисовывает «бегущую строку», из-за чего текст задваивается.
   В исходнике 670 событий, из них 334 — промежуточные кадры. После нормализации — 335 чистых реплик.

```bash
python3 build.py путь/к/файлу.json3    # пересобрать index.html с другими субтитрами
```

## Что в прототипе демонстрационное

- **Словарь** — 233 статьи, зашиты в файл, покрывают 77% слов этого видео. В рабочей версии
  здесь запрос к переводчику с учётом контекста фразы.
- **Вторая дорожка** — подстрочник по словам, поэтому читается коряво («когда обычный студент
  пишет работа»). Служебные слова отфильтрованы, иначе строка забивалась пометками вроде
  «неопред. артикль». В рабочей версии — машинный перевод реплики целиком.
- **Перевод нового видео** появляется после прогона через Claude (см. ниже). Пока перевода
  нет, вторая дорожка пустая — это честнее, чем показывать бессвязный подстрочник.
- **Алгоритм повторений** упрощён до SM-2-подобного. В проде — готовая библиотека FSRS.

## Живая версия на GitHub Pages: что там работает

https://kg881.github.io/razbor/ — демо-видео, расшифровка, тап по слову, карточки
и повторение работают полностью.

**Поле ссылки там не работает**, и это не баг, а защита браузера: страница открыта
по `https`, а бэкенд слушает `http://localhost` — обращения публичного сайта к локальной
сети браузер блокирует. Чтобы грузить свои видео, открывай приложение локально:
`http://localhost:8777`.

Починится двумя способами: поднять бэкенд на публичном хостинге с https (теперь это
реально — сервер делает один дешёвый запрос на видео раз в 6 часов, тяжёлое качает
клиент), либо собрать расширение, которому localhost не нужен вовсе.

## Известное ограничение

Родные субтитры YouTube могут остаться включёнными поверх видео, если они включены
в настройках аккаунта: `cc_load_policy: 0` не всегда перебивает пользовательскую настройку.
На проде решается инструкцией пользователю либо своим слоем управления треками.

## Бэкенд

Лежит в `server/`. Отвечает за то, чего нельзя делать в браузере: перевод с учётом
контекста (ключи провайдера остаются на сервере), нормализация json3 и общий кэш
переводов — второй ученик на том же видео обходится бесплатно.

```bash
cd server && npm install && npm start     # http://localhost:8788
```

| Эндпоинт | Назначение |
|---|---|
| `GET /api/health` | статус и размер кэша |
| `POST /api/cues` | json3 → чистые реплики с пословным таймингом |
| `POST /api/track` | **ссылка → подписанная ссылка на дорожку**; качает клиент сам. Основной путь |
| `POST /api/fetch` | то же, но качает сервер через yt-dlp. Запасной путь, медленнее |
| `POST /api/translate-video` | **перевод всего видео**: NDJSON-поток, пачки приезжают по готовности |
| `GET /api/translation/:id` | готовый перевод из кэша |
| `POST /api/word` | разбор слова в контексте фразы — для карточки |
| `POST /api/level-video` | оценка сложности реплик по CEFR, NDJSON-поток |
| `GET /api/levels/:id` | готовые оценки из кэша |
| `POST /api/idiom-video` + `GET /api/idioms/:id` | радар идиом: скан и кэш |
| `POST /api/offline` + `GET /api/offline/...` | офлайн-пакет: сборка, статус, отдача файлов |
| `POST /api/cues-store` | клиент присылает реплики на диск — для офлайн-сборки |
| `POST /api/anki` + `GET /api/anki/:name` | сборка и отдача колоды .apkg |
| `POST /api/clip` | вырезать кусок видео с фразой (зовётся при сохранении слова) |
| `GET /api/clips/:name` | отдача клипа, с поддержкой Range |

### Перевод: как это работает

Переводит Claude через локальный CLI (`claude -p`) — без ключей провайдера: CLI уже
авторизован подпиской. Словарная склейка по словам давала нечитаемое («они затем что они»)
и убрана совсем: субтитры рвут предложение посередине, переводить их можно только целыми
блоками и с оглядкой на соседние строки.

Конвейер (`server/src/translate-video.js` + `server/src/claude.js`):

- вставил ссылку → перевод стартует сам, ничего запускать не надо;
- пачки по 40 строк (первая — 15, чтобы начало появилось быстрее), каждой даётся
  хвост предыдущей и начало следующей как контекст;
- 5 воркеров параллельно, готовые пачки уезжают на экран сразу (NDJSON-поток);
- одно видео = одна задача: обновление страницы/повторная ссылка подключается к идущему
  переводу, а не запускает второй;
- кэш пишется после каждой пачки: обрыв или падение сервера теряет максимум пачку;
- обрыв клиента задачу не убивает — перевод дойдёт до конца и ляжет в кэш.

Флаги запуска CLI, каждый по итогам замера (см. комментарии в `claude.js`): `--tools ""`
обязателен — с инструментами модель на длинной пачке лезет в них и падает по `--max-turns`;
`cwd=tmpdir` — чтобы не подхватился CLAUDE.md; `--strict-mcp-config` — MCP не нужны.

Разбор одного слова — тоже Claude (`/api/word`): перевод в значении из фразы
(«plow» в «plow through life» → «рвануть вперёд», а не «пахать»), плюс заметка об
употреблении. Кэш на сервере и в localStorage.

Кнопка «Русский» в панели управления выключает русскую дорожку целиком (остаются
только английские субтитры) и запоминает выбор.

## Как устроена загрузка субтитров

Разделение труда, выбранное по замерам:

```
сервер (1 дешёвый запрос):  POST youtubei/v1/player, клиент ANDROID
                            → подписанная ссылка на дорожку
                            ↓
клиент (браузер/телефон):   GET по этой ссылке
                            → субтитры целиком, со своего адреса
```

Три замера 15.08.2026, на которых это держится:

1. Ссылка с watch-страницы (клиент WEB) несёт флаг `exp=xpe` и отдаёт **200 с пустым телом**.
   Флаг покрыт подписью, вырезать нельзя — будет 404.
2. Та же ссылка через InnerTube с клиентом **ANDROID** этого флага не несёт и отдаёт
   субтитры целиком. Версия клиента должна быть свежей: на устаревшей прилетает
   400 `FAILED_PRECONDITION` (именно на это я и напоролся сначала).
3. Подписанная ссылка **отдаёт CORS-заголовки** (`access-control-allow-origin` отражает
   любой Origin) и **не привязана к IP** (`ip=0.0.0.0`), живёт около 7 часов.

Отсюда главное: тяжёлую загрузку делает клиент со своего домашнего адреса, а сервер
только выдаёт ссылку. Лимиты YouTube размазываются по адресам пользователей вместо
одного серверного — и **расширение для этого не нужно**. Замер: новое видео грузится
за ~1 секунду против ~20 секунд через yt-dlp.

Ещё одна деталь: `tlang` (автоперевод дорожки силами YouTube) не используется — именно
он первым ловит 429. Вторую дорожку переводим у себя.

### Запасной путь через yt-dlp

`POST /api/fetch` принимает ссылку и возвращает готовые реплики: пользователю не нужен
ни вход в аккаунт, ни расширение. Внутри вызывается `yt-dlp` — свои обходы писать
бессмысленно, это гонка, которую не выиграть. Проверено 15.08.2026: голый `timedtext`
отдаёт 200 и пустое тело, InnerTube с клиентом ANDROID — 400 `failedPrecondition`,
yt-dlp работает.

**Ограничение архитектурное:** YouTube блокирует датацентровые IP и придушивает частые
запросы. Поэтому бэкенд рассчитан на запуск рядом с пользователем, на его домашнем адресе,
а не на общем облачном хостинге — там один общий IP быстро упрётся в лимит на всех сразу.
Под троттлингом загрузка занимает до двух минут, поэтому таймаут 180 с и кэш на 30 дней.

Требуется `yt-dlp`:

```bash
pip install -U yt-dlp
# если он не в PATH:  YTDLP_PATH=~/Library/Python/3.12/bin/yt-dlp npm start
```

## Как это делают конкуренты (разбор 15.08.2026)

Три рабочих способа добыть субтитры произвольного видео, по убыванию надёжности:

**1. Расширение в браузере** — Language Reactor, Migaku, FluentU, eJOY, Trancy на десктопе.
Работает внутри страницы youtube.com, поэтому субтитры достаются бесплатно из уже
аутентифицированной сессии пользователя, прошедшей бот-проверку. Самый устойчивый путь.

**2. Обёртка WebView вокруг youtube.com** — так сделан LingoTube на Android, дословно с их
сайта: «It shows YouTube website itself». Тот же приём, что у расширения, но в мобильном
приложении: страница грузится по-настоящему, субтитры берутся из её контекста.

**3. Серверная загрузка** — так работает импортёр LingQ, и **так работает наш `/api/fetch`**.
Способ рабочий, но ломается волнами: у LingQ публично зафиксированы поломки в сентябре 2024
и январе 2026 с формулировкой «broken due to youtube changes», причём Trancy и Migaku в те
же дни продолжали работать.

**Почему так.** Как только продукт уходит со страницы youtube.com, он наследует бот-детект.
Прямое подтверждение от поддержки Language Reactor: во встроенном плеере на их собственном
сайте YouTube выкидывает «verify you're not a robot», и «LR cannot completely prevent it on our end».

**Отсюда же понятно, зачем в этом сегменте Whisper.** Trancy заявляет прямо: «Trancy uses
OpenAI's Whisper speech-to-text service to asynchronously convert YouTube audio into subtitles»,
обработка 2-5 минут в очереди. То же у Migaku и eJOY. Это не про качество распознавания,
а про обход: ASR добавляют ровно там, где не могут надёжно получить оригинальную дорожку.

**Вывод для дорожной карты.** Расширение — не «приятное дополнение фазы 1», а единственный
устойчивый путь для десктопа. Для мобильного тот же эффект даёт WebView с youtube.com.
Серверная загрузка остаётся как запасной вариант и для десктопа без расширения.

## Демо-данные

В репозитории лежит фрагмент расшифровки на 3,5 минуты — этого хватает, чтобы
прогнать весь цикл. Полная расшифровка не публикуется: распространять субтитры
YouTube их правила не разрешают. Свой файл подкладывается так:

```bash
python3 build.py путь/к/файлу.json3
```

## Структура

```
build.py                     сборка index.html из шаблона и данных
template.html                разметка, стили, логика
serve.sh                     локальный сервер
tools/normalize_json3.py     json3 → чистые реплики с пословным таймингом
data/cues_demo.json          демо-фрагмент, 78 реплик
index.html                   собранный прототип (не редактировать руками)
data/translations/           переводы по videoId (кэш)
data/clips/                  вырезанные фрагменты фраз (кэш, вне git)
server/bin/ffmpeg            симлинк на статический ffmpeg (imageio-ffmpeg)
server/                      бэкенд: перевод (Claude CLI), дорожки, кэш
```

## Клипы фраз: как это добывается

Прямых ссылок на медиа InnerTube больше не отдаёт: ANDROID шлёт `adaptiveFormats`
без `url` и без `signatureCipher`, web-клиент — только storyboard'ы (SABR). Поэтому:

1. `yt-dlp -g` добывает прямые ссылки (нужен JS-рантайм — стоит `deno` в `~/.deno/bin`).
   Ссылки живут часами, кэшируются на 4 ч: следующие клипы того же видео режутся сразу.
2. Режет **свой** `ffmpeg`, а не `yt-dlp --download-sections`. Причина — замер 16.08.2026:
   yt-dlp передаёт ffmpeg браузерный User-Agent, а ссылки выписаны клиенту `ANDROID_VR`,
   и на таком мисматче googlevideo отвечает **403 примерно через раз** (4 падения из 9).
   С родным UA — 3 из 3. Плюс ретрай со сбросом кэша ссылок: часть edge-хостов
   googlevideo всё равно отдаёт 403, лечится новой выдачей.

Пережимаем на границах (`libx264 -crf 26`), не `-c copy`: иначе клип начинается
с ближайшего кейфрейма — на 480p это до пары секунд мимо начала фразы.

ffmpeg ставится без brew: `pip install --user imageio-ffmpeg`, бинарь линкуется
в `server/bin/ffmpeg`. Переопределяется через `FFMPEG_PATH`.
